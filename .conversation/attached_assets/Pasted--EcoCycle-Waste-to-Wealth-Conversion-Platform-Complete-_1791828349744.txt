## 3. Application Concept

EcoCycle connects people who want to dispose of recyclable waste with waste collectors, recycling companies, and administrators.

The platform converts waste into a potential source of income by managing collection, verification, inventory, recycling, sales, and payments.

Implement four distinct roles:

- **User:** Submits waste, books pickups, tracks requests, views receipts, and checks payments.
- **Collector:** Manages assigned pickups, verifies waste weight and quality, and records collection details.
- **Recycler:** Browses available materials, submits purchase offers, and tracks orders.
- **Admin:** Manages the complete platform, including users, rates, collections, inventory, sales, payments, and expenses.

Every role must have its own dashboard, navigation, and authorized functionality.

## 5. Complete Waste-to-Wealth Workflow

Implement the following functionality as real application features.

### Step 1: Registration and authentication

- Registration and login pages.
- Secure password hashing with bcrypt.
- JWT authentication with expiration.
- Protected frontend routes.
- Backend authentication middleware.
- Role-based authorization.
- User profile management.
- Logout functionality.
- Proper validation and error messages.

Public registration must not allow users to choose the `admin` role. Provide a secure way to create the first administrator, such as a documented seed script using environment configuration.

### Step 2: Waste submission

Allow users to submit:

- Plastic
- Paper
- Cardboard
- Metal
- Glass
- E-waste
- Organic waste

Each request should contain the waste category, estimated weight, pickup address, preferred date and time, optional description, and optional images.

Validate inputs on both frontend and backend.

### Step 3: Estimated waste value

Create an administrator-configurable rate system for each waste category.

Calculate:

`Estimated Value = Estimated Quantity × Rate per kg`

Show the rate and estimated total before submission.

Label the amount as an estimate, because the actual payment depends on verified weight and approved rates.

### Step 4: Pickup scheduling

Collectors should be able to view and manage pickup requests assigned to them.

Implement request statuses such as:

`Pending → Accepted → Scheduled → Collected → Verified → Completed`

Support rejection and cancellation where appropriate.

Users should be able to track their pickup status and view scheduled collection details.

Prevent unauthorized collectors from modifying requests assigned to other collectors.

### Step 5: Weight and quality verification

Allow authorized collectors to record:

- Actual measured weight.
- Material quality.
- Approved final rate per kilogram.
- Verification notes.
- Collector identity.
- Verification timestamp.

Calculate:

`Final Payable Amount = Verified Weight × Approved Rate per kg`

Keep estimated and verified values separate. Only authorized roles may perform verification.

### Step 6: Digital receipts

Generate a unique receipt after verification.

Include:

- Receipt ID.
- Pickup request ID.
- User details.
- Waste category.
- Estimated weight and value.
- Verified weight.
- Final rate.
- Final payable amount.
- Verification date.
- Payment status.

Users must be able to view and print or download receipts.

### Step 7: Inventory and QR tracking

After successful verification, create an inventory batch with:

- Unique batch ID.
- Waste category.
- Verified quantity.
- Available quantity.
- Reserved quantity.
- Quality classification.
- Collection source.
- Collection date.
- Processing status.
- Storage location, if applicable.

Generate a QR code that identifies the batch and links to its authorized details page.

Maintain an inventory history and prevent overselling or allocating the same quantity twice.

### Step 8: Waste processing

Support suitable workflows for:

- Plastic, paper, cardboard, metal, and glass recycling.
- Authorized e-waste processing.
- Organic waste composting or biogas processing.

Allow administrators to manage processing destinations and statuses.

Do not claim that EcoCycle physically processes waste unless that operation is genuinely provided.

### Step 9: Recycler matching and purchase offers

Create a recycler dashboard where approved recycling companies can:

- Browse available material batches.
- Filter by category and quality.
- View available quantities.
- Specify required quantities.
- Submit offers with proposed rates.
- View offer acceptance or rejection.
- Track orders and transactions.

Match buyers and materials based on category compatibility, quantity requirements, quality, and offered price.

Show understandable reasons why a particular offer matches a batch.

### Step 10: Sales and payments

When an authorized offer is accepted:

- Create a sales order.
- Reserve the required inventory.
- Record the agreed price and quantity.
- Track dispatch and sale status.
- Update inventory after the appropriate confirmed transaction stage.
- Record payment status and transaction references.

Distinguish between user payouts, recycler payments, platform revenue, operating expenses, and profit or loss.

Initially support manually recorded payments. Do not mark payments as completed without confirmation.

Payment gateway integration can be added later.

### Step 11: Admin dashboard

Build a comprehensive dashboard showing:

- Total users.
- Active collectors and recyclers.
- Pending and completed pickups.
- Waste collected by category.
- Available and reserved inventory.
- Recycler offers.
- Sales and revenue.
- User payout liabilities.
- Recycler payment status.
- Operating expenses.
- Recent transactions.
- Pickup and sales trends.

Include management pages for users, collectors, recyclers, waste rates, pickup requests, inventory, processing, offers, sales, payments, and expenses.

Implement search, filtering, pagination, confirmation dialogs, and validation.

### Step 12: Impact and analytics
