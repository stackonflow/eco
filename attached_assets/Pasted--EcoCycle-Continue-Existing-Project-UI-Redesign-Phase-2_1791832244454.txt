## 4. Priority Two: Implement Phase 2 — Waste Submissions and Rate Management

Once the existing UI and authentication are verified, implement Phase 2 end-to-end.

### A. Waste categories

Support these categories:

- Plastic
- Paper
- Cardboard
- Metal
- Glass
- E-waste
- Organic waste

### B. WasteRate model

Create or update a Mongoose model containing:

- Waste category.
- Rate per kilogram.
- Active/inactive status.
- Created and updated timestamps.

Only administrators can create, update, activate, or deactivate rates.

Do not let users modify prices or submit arbitrary user roles.

### C. Waste submission form

Create a polished, responsive page where authenticated users can submit waste collection requests.

Include:
- Waste category.
- Estimated quantity in kilograms.
- Pickup address.
- Preferred pickup date and time.
- Optional description.
- Optional image upload if the existing infrastructure supports it.

Validate required fields, positive quantities, reasonable quantity limits, and valid pickup dates.

Display the current active rate and calculate the estimated value automatically.

Formula:

Estimated value = estimated quantity × current rate per kilogram.

Clearly state that the amount is an estimate and may change after physical weight and quality verification.

### D. PickupRequest model

Create or update a Mongoose model containing:

- User reference.
- Waste category.
- Estimated quantity.
- Pickup address.
- Preferred date and time.
- Optional description.
- Rate snapshot used for the estimate.
- Estimated value.
- Request status.
- Created and updated timestamps.

The backend must retrieve the applicable active rate from MongoDB and calculate the estimated value itself.

Never trust a price, estimated total, user ID, or role supplied by the frontend.

### E. Backend APIs

Implement authenticated endpoints for:

- Listing active waste rates.
- Creating waste requests.
- Listing the logged-in user's requests.
- Viewing an individual request with appropriate authorization.
- Admin listing and management of requests.
- Admin creation, editing, and activation/deactivation of rates.

Use input validation, consistent responses, appropriate HTTP status codes, and centralized error handling.

Users must only access their own requests. Administrators may manage all requests.

### F. User interface

Create a "Submit Waste" page and a "My Waste Requests" page.

The request list should show:
- Waste category.
- Estimated quantity.
- Rate per kilogram.
- Estimated value.
- Submission date.
- Current status.

Create an administrator rate-management page with tables, forms, validation, loading states, success/error feedback, and confirmation dialogs where appropriate.

Make the UI cohesive with the redesigned landing page. Do not introduce a separate design system.

### G. Database persistence

All waste rates and requests must be stored in MongoDB Atlas.

Verify that:
- Requests remain available after page refresh.
- Users can see their own saved requests.
- Rate changes are reflected in new estimates.
- Previously submitted requests retain their historical rate and estimated value.
- Inactive rates cannot be used for new requests.
