## PART A — Redesign the UI Before Phase 2

### 1. Design direction

Use the uploaded clinic website screenshot as a reference for the quality, composition, typography, spacing, and visual hierarchy—not its medical content or branding.

I want EcoCycle to look like a website intentionally designed by a professional product designer, not a generic AI-generated template.

**Avoid the typical "vibe-coded" appearance.** Specifically, do not use:
- Excessive glowing borders and neon outlines.
- Blue-purple gradients on every card.
- Unnecessary glassmorphism or blur effects.
- Huge rounded cards for every section.
- Repeated card grids where simpler layouts would work better.
- Random decorative circles and floating elements.
- Excessive animations, bounce effects, and hover transformations.
- Emoji as a substitute for a coherent icon system.
- Generic dashboard templates with no visual identity.
- Inconsistent spacing, typography, or button styles.
- Artificial statistics, fake testimonials, or invented impact claims.

Do not simply change colors on the existing layout. Rethink the page composition, hierarchy, and spacing.

### 3. EcoCycle visual identity

Use a refined sustainability-focused palette:
- Deep forest green for primary branding and important actions.
- Muted emerald for accents.
- Warm off-white and light neutral backgrounds.
- Dark charcoal or deep green for headings.
- Soft sage tones for secondary surfaces.
- Restrained orange or amber accents only where useful.

Use a consistent typography system, a limited set of spacing values, subtle borders, and carefully selected shadows.

Buttons, forms, navigation, headings, icons, and dashboards must share a consistent design language.

Use Lucide icons where icons are necessary. Use high-quality, relevant recycling imagery or illustrations. Do not use random stock images unrelated to waste management.

## PART B — Phase 2: Waste Submissions and Rate Management

After the redesign is complete, implement Phase 2 using the existing MERN architecture.

### 1. Waste categories

Support:
- Plastic
- Paper
- Cardboard
- Metal
- Glass
- E-waste
- Organic waste

### 2. Waste rate management

Create a Mongoose `WasteRate` model containing:
- Waste category.
- Rate per kilogram.
- Active/inactive status.
- Created and updated timestamps.

Implement admin-only functionality to create, edit, activate, and deactivate rates.

Only authorized administrators can modify rates. Ordinary users must never be able to change prices.

### 3. Waste submission form

Create a polished, responsive waste submission page with:
- Waste category selector.
- Estimated quantity in kilograms.
- Pickup address.
- Preferred pickup date and time.
- Optional description.
- Optional image upload if the existing infrastructure supports it.

Validate required fields, positive quantities, and valid future pickup dates where applicable.

Display the current rate and calculate the estimated value dynamically.

Formula:

`Estimated Value = Estimated Quantity (kg) × Current Rate per kg`

Clearly state that this is an estimate, not a guaranteed payout.

### 4. Backend and database

Create a `PickupRequest` Mongoose model containing:
- User reference.
- Waste category.
- Estimated quantity.
- Pickup address.
- Preferred date and time.
- Optional description.
- Rate snapshot used for the estimate.
- Estimated value.
- Request status.
- Created and updated timestamps.

Store all requests in MongoDB Atlas.

Capture the applicable rate on the backend when the request is created. Never trust a price or user ID supplied by the frontend.

### 5. APIs

Implement authenticated APIs for:
- Retrieving active waste rates.
- Creating waste submission requests.
- Retrieving the logged-in user's requests.
- Retrieving an individual request with appropriate authorization.
- Admin listing and management of all requests.
- Admin creation and management of waste rates.

Use input validation, appropriate HTTP status codes, centralized error handling, and role-based authorization.

Users must only be able to access their own requests. Admins may access requests across users.

### 6. User interface

Create a "Submit Waste" page and a "My Waste Requests" page.

The request list should show:
- Waste category.
- Estimated quantity.
- Rate per kilogram.
- Estimated value.
- Submission date.
- Current status.

Create an admin rate-management interface with clear forms, tables, loading states, confirmation dialogs, and success/error feedback.

Match these pages to the redesigned EcoCycle visual identity. Do not introduce a different design system for Phase 2.

### 7. Testing

Test:
- Valid waste submission.
- Invalid and missing fields.
- Invalid quantities.
- Rate calculation.
- Inactive or missing rates.
- Unauthorized requests.
- User access restrictions.
- Admin-only rate management.
- MongoDB persistence after refresh.
- Existing authentication functionality.

Use actual database records, not fake data. Do not claim a test passed unless it was actually run.

When finished, provide:

- Features completed.
- API endpoints added.
- Tests performed and their actual results.
- Any remaining issues or setup requirements.
